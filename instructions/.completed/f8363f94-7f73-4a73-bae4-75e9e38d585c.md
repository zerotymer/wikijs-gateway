# Step 8: 역할 기반 인증 분리 (읽기/관리자)

## 목표

단일 토큰 구조를 역할 기반 이중 토큰으로 교체한다.

- **읽기(전역)**: 기존 Wiki.js 읽기 권한을 그대로 사용. 일반 `GATEWAY_TOKEN`으로 접근.
- **관리자(쓰기)**: 별도의 `GATEWAY_ADMIN_TOKEN`으로만 등록·수정 허용. Wiki.js 측도 별도 쓰기 전용 토큰 사용.

## 환경 변수 변경

### 추가

| 변수 | 필수 | 설명 |
|------|------|------|
| `WIKIJS_ADMIN_API_TOKEN` | ✅ | Wiki.js 쓰기 전용 API 토큰 (write:pages 권한) |
| `GATEWAY_ADMIN_TOKEN` | ✅ | 관리자 Gateway 접근용 Bearer 토큰 |

### 기존 역할 변경

| 변수 | 변경 전 | 변경 후 |
|------|---------|---------|
| `WIKIJS_API_TOKEN` | read+write 겸용 | **읽기 전용** (read:pages, read:source) |
| `GATEWAY_TOKEN` | 모든 요청 허용 | **읽기 전용** 엔드포인트만 허용 |

## 구현 범위

### 1. `app/config.py`

- `wikijs_admin_api_token: str` 필드 추가
- `gateway_admin_token: str` 필드 추가

### 2. `app/auth.py`

- `verify_token(credentials, settings)` — `GATEWAY_TOKEN`으로 읽기 권한 검증 (기존 동작 유지)
- `verify_admin_token(credentials, settings)` — `GATEWAY_ADMIN_TOKEN`으로 관리자 권한 검증 (신규)
- 두 함수 모두 토큰 불일치 시 `401` / `403` 반환

### 3. `app/wikijs_client.py`

- `WikiJsClient.__init__`에 `admin_api_token: str | None = None` 파라미터 추가
- 쓰기 mutation (`create_page`, `update_page`, `upsert_page`)은 `admin_api_token`이 있으면 해당 토큰 사용
- 없으면 기존 `api_token` 사용 (하위 호환)
- `lifespan`에서 `WikiJsClient(url, token, admin_token=admin_token)` 형태로 초기화

### 4. `app/main.py`

엔드포인트별 의존성 변경:

| 엔드포인트 | 변경 전 | 변경 후 |
|-----------|---------|---------|
| `GET /health` | `verify_token` | `verify_token` (유지) |
| `GET /pages/by-path` | `verify_token` | `verify_token` (유지) |
| `GET /pages/search` | `verify_token` | `verify_token` (유지) |
| `POST /pages/dry-run` | `verify_token` | `verify_admin_token` |
| `POST /pages/patch-section` | `verify_token` | `verify_admin_token` |
| `POST /pages/upsert` | `verify_token` | `verify_admin_token` |

> **근거**: dry-run도 쓰기 의도를 가진 요청이므로 관리자 인증 필요.

### 5. `.env.example`

신규 변수 2개 추가 및 주석으로 역할 구분 명시.

## Wiki.js 토큰 권한 분리 가이드

Wiki.js Admin 패널에서 API 토큰 2개 발급:

| 토큰 변수 | 부여 권한 |
|-----------|-----------|
| `WIKIJS_API_TOKEN` | `read:pages`, `read:source` |
| `WIKIJS_ADMIN_API_TOKEN` | `read:pages`, `read:source`, `write:pages` |

`manage:system`, `delete:pages`, `manage:users`는 부여하지 않는다.
