# Step 7: 배치(Bulk) API 확장

## 목표

단건 처리만 지원하는 기존 API를 다건·혼합 유형 배치 처리로 확장한다.

- **다건 조회**: 여러 경로의 페이지를 한 번에 가져온다.
- **혼합 배치 쓰기**: upsert / patch-section / dry-run 항목을 하나의 요청 배열로 묶어 전송한다.
- **개별 결과 반환**: 일부 항목 실패 시에도 나머지는 계속 처리하고 항목별 성공/실패를 응답에 담는다.
- **병렬 실행**: `asyncio.gather` + `asyncio.Semaphore`로 동시 처리한다.

## 신규 엔드포인트

### 1. `POST /pages/by-paths` — 다건 페이지 조회
> **entity**: `b132a580-8f20-445f-924c-964523fb24c2` (API — POST /pages/by-paths)

```
POST /pages/by-paths
Authorization: Bearer <GATEWAY_TOKEN>
```

**Request body**

```json
{
  "paths": [
    { "path": "/docs/intro", "locale": "ko" },
    { "path": "/docs/api" }
  ]
}
```

- `locale` 생략 시 `DEFAULT_LOCALE` 적용.
- 최대 `BATCH_MAX_SIZE`(기본 50)개.

**Response 200**

```json
{
  "ok": true,
  "results": [
    {
      "index": 0,
      "path": "/docs/intro",
      "ok": true,
      "page": { /* PageResponse 필드 전체 */ }
    },
    {
      "index": 1,
      "path": "/docs/api",
      "ok": false,
      "error": "PAGE_NOT_FOUND"
    }
  ],
  "summary": { "total": 2, "succeeded": 1, "failed": 1 }
}
```

### 2. `POST /pages/bulk` — 혼합 유형 배치 작업
> **entity**: `60269379-af6f-47a4-9011-57d92c4f9299` (API — POST /pages/bulk)

```
POST /pages/bulk
Authorization: Bearer <GATEWAY_TOKEN>
```

**Request body**

각 항목은 `type` 필드로 구분한다.

```json
{
  "operations": [
    {
      "id": "op-upsert-1",
      "type": "upsert",
      "path": "/agent/page1",
      "locale": "ko",
      "title": "페이지 제목",
      "description": "",
      "content": "# 내용",
      "editor": "markdown",
      "isPublished": true,
      "isPrivate": false,
      "tags": []
    },
    {
      "id": "op-patch-1",
      "type": "patch-section",
      "path": "/agent/page2",
      "locale": "ko",
      "baseHash": "sha256hex...",
      "operation": {
        "type": "replace_between_markers",
        "name": "summary",
        "content": "## 새 내용"
      }
    },
    {
      "id": "op-dry-1",
      "type": "dry-run",
      "path": "/agent/page3",
      "locale": "ko",
      "baseHash": "sha256hex...",
      "operation": {
        "type": "append_under_heading",
        "heading": "## 항목",
        "content": "- 새 항목",
        "create_heading": false
      }
    }
  ]
}
```

- `id`: 클라이언트가 결과 매칭에 사용하는 임의 문자열. 중복 허용.
- 최대 `BATCH_MAX_SIZE`(기본 50)개.

**Response 200**

```json
{
  "ok": true,
  "results": [
    {
      "id": "op-upsert-1",
      "type": "upsert",
      "ok": true,
      "result": {
        "ok": true,
        "created": true,
        "pageId": 42,
        "path": "/agent/page1"
      }
    },
    {
      "id": "op-patch-1",
      "type": "patch-section",
      "ok": false,
      "error": "PAGE_CHANGED",
      "currentHash": "sha256hex..."
    },
    {
      "id": "op-dry-1",
      "type": "dry-run",
      "ok": true,
      "result": {
        "ok": true,
        "mode": "dry_run",
        "changed": true,
        "diff": "...",
        "newHash": "sha256hex..."
      }
    }
  ],
  "summary": { "total": 3, "succeeded": 2, "failed": 1 }
}
```

항목별 실패는 HTTP 200으로 반환한다. (요청 처리 자체는 성공)

## 구현 세부 사항

### 환경 변수 추가

| 변수 | 기본값 | 설명 |
|---|---|---|
| `BATCH_MAX_SIZE` | `50` | 배치 요청당 최대 항목 수 |
| `BATCH_CONCURRENCY` | `10` | 동시 실행 최대 goroutine(asyncio task) 수 |

`app/config.py`의 `Settings` 클래스에 추가한다.

### 병렬 실행 패턴

```python
import asyncio

async def run_batch(tasks, concurrency: int):
    sem = asyncio.Semaphore(concurrency)

    async def with_sem(coro):
        async with sem:
            return await coro

    return await asyncio.gather(*[with_sem(t) for t in tasks], return_exceptions=True)
```

`return_exceptions=True`를 사용해 개별 예외가 전체 gather를 중단하지 않도록 한다.

### 최대 크기 초과 시 응답

```json
HTTP 422
{
  "error": "BATCH_TOO_LARGE",
  "message": "최대 50개까지 처리할 수 있습니다.",
  "received": 75,
  "limit": 50
}
```

### 모드 검증

- `by-paths`: `read_only` 포함 모든 모드 허용.
- `bulk` 내 `upsert` / `patch-section`: `write` 모드에서만 실제 반영, `dry_run`이면 dry-run 결과를 item 결과로 반환.
- `bulk` 내 `dry-run`: `dry_run` 이상 모드 허용.
- 개별 항목이 현재 모드에서 허용되지 않는 경우 해당 항목 `ok: false`, `error: "MODE_NOT_ALLOWED"`.

### Audit 로깅

`bulk` 엔드포인트의 각 항목에 대해 기존 `write_audit`을 그대로 호출한다.  
`by-paths`는 읽기 전용이므로 audit 불필요.

## 추가할 pydantic 모델 (요약)

```python
# 배치 조회
class PathItem(BaseModel):
    path: str
    locale: str = ""

class BulkFetchRequest(BaseModel):
    paths: list[PathItem]

class BulkFetchItem(BaseModel):
    index: int
    path: str
    ok: bool
    page: PageResponse | None = None
    error: str | None = None

class BulkFetchResponse(BaseModel):
    ok: bool
    results: list[BulkFetchItem]
    summary: dict  # total, succeeded, failed

# 배치 작업
class BulkUpsertOperation(UpsertRequest):
    id: str
    type: Literal["upsert"]

class BulkPatchOperation(PatchSectionRequest):
    id: str
    type: Literal["patch-section"]

class BulkDryRunOperation(DryRunRequest):
    id: str
    type: Literal["dry-run"]

BulkOperationItem = Annotated[
    BulkUpsertOperation | BulkPatchOperation | BulkDryRunOperation,
    Field(discriminator="type")
]

class BulkRequest(BaseModel):
    operations: list[BulkOperationItem]

class BulkItemResult(BaseModel):
    id: str
    type: str
    ok: bool
    result: dict | None = None   # 성공 시 해당 endpoint 응답
    error: str | None = None     # 실패 시 에러 코드
    message: str | None = None   # 실패 시 상세 메시지
    currentHash: str | None = None  # PAGE_CHANGED 시

class BulkResponse(BaseModel):
    ok: bool
    results: list[BulkItemResult]
    summary: dict  # total, succeeded, failed
```
