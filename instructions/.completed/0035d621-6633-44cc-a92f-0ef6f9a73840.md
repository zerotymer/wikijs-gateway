# Docker 이미지 빌드·배포

## 목표

게이트웨이 이미지를 1회 빌드해 두 레지스트리에 게시한다. 서버측 run/배포는
범위 밖 — **이미지 빌드·push만**.

- Docker Hub: `zerotymer/wikijs-gateway`
- GHCR: `ghcr.io/zerotymer/wikijs-gateway`
- 태그: 버전(예: `1.0.3`) + `latest` (버전 관리)

> 당초 Nexus(`nexus.zerotymer.net/docker/...`)를 대상으로 했으나, 경로형 docker
> 레지스트리는 docker 클라이언트가 `/v2/`를 호스트 루트로만 호출해 인증이 반복
> 실패(429)했다. Nexus docker repo를 폐기하고 GHCR로 전환.

## 구현

- `.dockerignore` 추가 — `.venv`·`.git`·`tests`·`.env` 등 빌드 컨텍스트 제외.
- `scripts/docker-publish.sh` 추가 — `<version>` 인자로 1회 빌드 → 양쪽 레지스트리
  × {version, latest} 태그 → push. 레지스트리 경로는 env(`DOCKERHUB_IMAGE`,
  `GHCR_IMAGE`)로 override 가능. `docker login`은 사전 완료 가정.
- `Dockerfile`은 현행 유지(빌드 정상). 이미지 내부 `pip install`은 기존대로 PyPI 사용.

## 검증

- `docker build` 성공(fastapi-mcp==0.4.0 포함).
- 컨테이너 기동 확인: `/health` → `{"ok":true,"wikijsReachable":false}`,
  `POST /mcp` initialize → HTTP 200.
- `bash -n`으로 스크립트 문법 검사 통과.

## 사용법

```bash
docker login                          # Docker Hub
gh auth refresh -h github.com -s write:packages
gh auth token | docker login ghcr.io -u zerotymer --password-stdin   # GHCR
scripts/docker-publish.sh 1.0.3       # 1.0.3 + latest 를 양쪽에 push
```

## 메모

- push는 외부 공개 게시이므로 자동 실행하지 않는다 — 운영자가 직접 스크립트 실행.
- CI 자동화(GitHub Actions)는 YAGNI — 수요 생기면 추가.
