# Issue #19 — by-uuid 대소문자 fallback + search 502

브랜치: `fix/issue-19-uuid-search/51e3730a`

## 결정 (이슈 작성자 확인)

| 항목 | 결정 |
|---|---|
| A1 | 대소문자 **정확 일치 우선**(기본 파일 보호). 없을 때만 대소문자 무시 fallback. fallback 후보가 2개 이상이면 409 `ambiguous-uuid` |
| A2 | 수정 대상 |
| A3 | 운영 배포는 별도 지시서(CI 이미지 배포)로 체계화 |
| A4 | 읽기 엔드포인트 공개 유지 (변경 없음) |

## 원인

- **A2**: 검색 쿼리가 `PageSearchResult.updatedAt`을 요청. Wiki.js 2.x 스키마
  (`server/graph/schemas/page.graphql`)에 없는 필드 → Wiki.js가 HTTP 400 + `errors`.
  `raise_for_status()`가 먼저 터져 `wikijs-unreachable`로 오분류됨.
  추가로 `PageSearchResult.id`는 `String!` → Rust `i64` 역직렬화도 실패했을 것.
- **A1**: `type` 지정 시 `type/uuid`를 그대로 조회, 미지정 시 `pages.list`에서 대소문자 구분 비교 + 첫 일치 반환.

## 작업

- [x] 검색 쿼리에서 `updatedAt` 제거, 응답 모델 `SearchResultItem.updatedAt` 제거 (Python/Rust)
- [x] Rust `SearchResultItem.id`: 문자열/숫자 모두 수용, 응답은 숫자 유지
- [x] 4xx 응답에 GraphQL `errors` 본문이 있으면 `wikijs-error`로 분류 (Python `_json_body`, Rust `post`)
- [x] `find_paths_by_uuid(uuid, type)`: `pages.list` 기반, 정확 일치 1개 우선 → 대소문자 무시 후보 전체
- [x] 리졸버: 후보 2개 이상 → 409 `ambiguous-uuid` + `candidates`; `type` 지정 시에도 동일 규칙, 응답 `type`은 실제 저장 경로 prefix
