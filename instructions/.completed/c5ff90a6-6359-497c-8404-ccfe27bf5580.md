# Step 6: 페이지 검색 엔드포인트 구현

## 목적

현재 Gateway에 검색 기능이 없다. Wiki.js GraphQL `pages.search` 쿼리를 래핑하는 `GET /pages/search` 엔드포인트를 추가한다.

검색은 읽기 전용 작업이므로 `read_only` 모드에서도 사용 가능하다.

---

## 구현 범위

### 1. `app/models.py` — 모델 추가

```python
class SearchResultItem(BaseModel):
    id: int
    path: str
    title: str
    description: str
    locale: str
    updatedAt: str

class SearchResponse(BaseModel):
    ok: bool
    query: str
    results: list[SearchResultItem]
    suggestions: list[str]
    totalHits: int
```

### 2. `app/wikijs_client.py` — GraphQL 쿼리 + 메서드 추가

GraphQL 쿼리:

```graphql
query SearchPages($query: String!, $locale: String) {
  pages {
    search(query: $query, locale: $locale) {
      results {
        id
        path
        title
        description
        locale
        updatedAt
      }
      suggestions
      totalHits
    }
  }
}
```

`WikiJsClient`에 메서드 추가:

```python
async def search_pages(self, query: str, locale: str | None = None) -> dict:
    variables: dict = {"query": query}
    if locale:
        variables["locale"] = locale
    # POST to graphql, raise WikiJsError on errors
    # return body["data"]["pages"]["search"]
```

### 4. `tests/test_routes_search.py` — 테스트

`respx` mock으로 Wiki.js GraphQL을 패치:

**테스트 케이스:**
- `test_search_returns_results`: 정상 응답 (2개 결과) 반환 검증
- `test_search_empty_query`: `query=""` → 422 또는 빈 결과 반환 (구현에 따라)
- `test_search_limit`: `limit=1`이면 결과 1개만 반환
- `test_search_wikijs_error`: WikiJsError 시 502 반환

## 참고

- Wiki.js GraphQL search는 인증된 API token 권한 `read:pages` 로 동작한다.
- `totalHits`는 Wiki.js가 반환하는 값이며 실제 결과 수와 다를 수 있다 (full-text index 기준).
- `suggestions`는 오타 교정 제안으로, Wiki.js가 빈 배열을 반환할 수 있다.
