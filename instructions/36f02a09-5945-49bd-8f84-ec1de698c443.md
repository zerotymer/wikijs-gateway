# GET /pages/download

## 배경

현재 모든 라우트가 JSON만 반환한다. markdown 원문은 `PageResponse.content`
필드에 문자열로 들어있어 파일로 저장하려면 `jq` 같은 외부 도구가 필요하다.
`curl` 단독으로 바로 파일을 받을 수 있어야 한다 (의존성 추가 금지).

## 설계

`GET /pages/download` — 인증 없음 (읽기 라우트 정책 동일)

| 파라미터 | 필수 | 기본 | 설명 |
|---|---|---|---|
| `uuid` | ✅ | — | 조회 키 |
| `type` | — | — | 생략 시 `find_path_by_uuid`로 역추적 (`/pages/by-uuid`와 동일) |
| `locale` | — | `ko` | 내용 선택에만 사용. 파일명에는 반영하지 않음 |
| `filename` | — | — | 확장자 없는 base name. 생략 시 `{TYPE}` (해석된 type 대문자화) |

- 응답 body는 `page.content` 원문 그대로 (JSON 래핑 없음)
- `Content-Type: text/markdown; charset=utf-8`
- `Content-Disposition: attachment; filename="SKILL.md"`
- 확장자는 항상 `.md` 고정
- type 해석 실패 시 파일명 폴백은 `noname.md`
- 동일 파일명 충돌은 사용자 책임 (서버가 접미사를 붙이지 않음)

### filename 검증

`^[A-Za-z0-9._-]{1,64}$`, `..` 포함 불가. 실패 시 422 `INVALID_FILENAME`.
슬래시·비ASCII 불허 — HTTP 헤더 주입 및 경로 이탈 차단 (trust boundary).
해석된 `type`도 같은 정규식을 통과해야 파일명에 사용한다 (wiki 데이터가
헤더로 흘러가는 경로이므로).

### 사용 예

```bash
curl -fOJ 'http://127.0.0.1:8088/pages/download?uuid=<UUID>'                   # SKILL.md (ko)
curl -fOJ 'http://127.0.0.1:8088/pages/download?uuid=<UUID>&locale=en'         # SKILL.md (en)
curl -fOJ 'http://127.0.0.1:8088/pages/download?uuid=<UUID>&filename=SKILL_ko' # SKILL_ko.md
```

## 결정 사항

- zip으로 en+ko 동시 다운로드는 하지 않는다. 두 번 호출한다.
- MCP tool로는 노출하지 않는다 — `get_page_by_uuid`가 이미 content를 준다.
- `filename`에 `.md`를 붙여 보내도 받아준다 (뒤의 `.md` 1회 strip).
  `SKILL.md.md` 방지용.
