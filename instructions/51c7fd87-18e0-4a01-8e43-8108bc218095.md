# API v2 계약 — Wiki.js 동일 포트 L7 라우팅

> **이 지시서는 계약(설계) 초안이다. 구현은 별도 승인 후 진행한다.**
> 계약은 **FastAPI판과 Rust판(Axum + rmcp) 모두** 동일하게 구현한다.

- 적용 정책: `skills/multi-container-endpoint-architecture` (일부 수정, §7)
- 릴리스: gateway **2.0.0** (현재 `v1.0.x`). 기존 경로·응답과 하위 호환 없음
  (로컬 `127.0.0.1:8088` 배포는 개발 전용이므로 이행 기간 불필요)

## 결정 사항

| 항목 | 결정 |
|---|---|
| Base path | `/api/v2` — **API 경로 major = 이미지 semver major**. 이후 breaking 변경 시 둘 다 올린다 |
| service slug | 없음. 공유 호스트 전체가 wiki |
| 구현 대상 | FastAPI판·Rust판 동일 계약. 이미지 태그 `2.x.y-python` / `2.x.y-rust` |
| reverse proxy | 사용자 측 설정. 소스 구현 대상 아님 → §8은 운영자 안내 |
| 레거시 `/pages/*`, `/health`, `/mcp` | 제거 (alias 없음, 404) |
| 잠금 충돌 | 409 + problem+json |
| 쓰기 후 hash | **재조회한 실제 `contentHash` 반환** (§5) |

## 1. 목표 토폴로지

```
            https://<wiki-host>/   (단일 공개 포트)
                     │
       Reverse Proxy (사용자 설정, L7 path prefix)
          ┌──────────┴───────────────────┐
     /api/v2/*                      그 외 전부 (/)
          │                              │
  wikijs-gateway:8080               wiki:3000 (Wiki.js)
  (python | rust 태그)                    ▲
          └────── GraphQL (내부망) ───────┘
```

- 경로 재작성 없음. gateway 앱이 `/api/v2/...`를 **자기 경로로 직접** 서빙한다.
- `/health/*`는 base 밖 → proxy가 `/api/v2/`만 넘기면 자동으로 비공개.

## 2. Wiki.js 점유 경로 (소스 확인: requarks/wiki `server/`)

| 경로 | 용도 |
|---|---|
| `/` + `/*` catch-all | 페이지 렌더 (`controllers/common.js:417`) — **없는 경로도 200 HTML("페이지 생성")** |
| `/a` `/d` `/e` `/h` `/i` `/p` `/s` `/t` (+`/*`) | 관리·다운로드·편집·히스토리·ID·프로필·소스·태그 |
| `/u` | 업로드 |
| `/graphql` | GraphQL API (+ subscriptions) |
| `/login*` `/logout` `/register` `/verify/*` `/login-reset/*` | 인증 |
| `/_assets/*` `/_userav/*` | 정적 자산, 아바타 |
| `/healthz` `/robots.txt` `/.well-known/*` | 운영 |

페이지 경로 예약 규칙 (`helpers/page.js:104` `isReservedPath`): 첫 세그먼트 길이 ≤ 1,
locale 형태(`^[a-z]{2}(-[a-z]{2})?$`), `data.yml`의 `reservedPaths`(목록 미확인).
→ **`api`는 예약되지 않는다.** G1로 막는다.

## 3. v2 엔드포인트

Base: `/api/v2`

| Method | Path | 인증 | operation_id (MCP tool) | 이전 경로 | 비고 |
|---|---|---|---|---|---|
| GET | `/pages?path=&locale=` | - | `get_page_by_path` | `GET /pages/by-path` | 응답 `ETag: "<contentHash>"` |
| GET | `/pages/search?q=&locale=&limit=` | - | `search_pages` | `GET /pages/search` | 도메인 액션 예외 |
| POST | `/pages/batch-get` | - | `get_pages_by_paths` | `POST /pages/by-paths` | 도메인 액션 예외 |
| PUT | `/pages` | Bearer | `upsert_page` | `POST /pages/upsert` | 생성 201 / 수정 200. 수정 시 `baseHash` 필수 |
| POST | `/pages/patches` | Bearer | `patch_section` | `POST /pages/patch-section` | |
| POST | `/pages/patches/preview` | Bearer | `dry_run_patch` | `POST /pages/dry-run` | 쓰기 없음, audit 기록 |
| GET | `/documents/{uuid}?type=` | - | `get_page_by_uuid` | `GET /pages/by-uuid` | en+ko |
| GET | `/documents/{uuid}/raw?locale=&filename=` | - | (tool 제외) | `GET /pages/download` | `text/markdown`, attachment |
| POST/GET/DELETE | `/mcp` | 쓰기 tool만 | — | `/mcp` | Streamable HTTP |
| GET | `/openapi.json` | - | (제외) | `/openapi.json` | FastAPI `/docs` `/redoc` 비활성 |

내부 전용 (proxy 대상 아님): `GET /health/live`, `GET /health/ready` (Wiki.js 도달 여부)

설계 규칙:
- **`/pages/{param}` 형태를 만들지 않는다** (`search`, `batch-get`, `patches`와 리터럴 충돌). 식별자 조회는 `/documents/{uuid}`.
- MCP tool 이름 = operation_id 유지 → MCP 클라이언트는 URL만 변경.
- 모든 응답(오류 포함)에 `X-Served-By: wikijs-gateway`.

## 4. 오류 계약

- REST 오류는 `application/problem+json` (RFC 9457). `type`은 `urn:wikijs-gateway:problem:<code>`.

| status | type code | 상황 |
|---|---|---|
| 401 | `unauthorized` | Bearer 없음 |
| 403 | `forbidden` | 토큰 불일치 |
| 404 | `page-not-found` | 페이지 없음 (by-uuid는 en·ko 모두 없을 때) |
| 409 | `page-changed` | `baseHash` 불일치. 확장 필드 `currentHash` |
| 422 | `validation-error` / `patch-error` / `reserved-path` | 입력 오류, heading/marker 없음, `api/` 경로 쓰기 |
| 428 | `precondition-required` | 기존 페이지 수정 upsert에 `baseHash` 누락 |
| 502 | `wikijs-error` / `wikijs-unreachable` | 상류 오류. 내부 메시지는 audit/log에만 |

- MCP tool 오류는 HTTP 계약 밖: `CallToolResult.isError = true` + 위 problem 객체를 JSON text로.

## 5. 잠금(Optimistic Lock) v2 계약

### 현재 결함 (코드 확인)

| # | 결함 | 위치 | 영향 |
|---|---|---|---|
| L1 | 충돌 시 **HTTP 200 + `ok:false`**. OpenAPI엔 403 선언 | `main.py:232`, `:290` | 상태 코드만 보는 클라이언트가 성공으로 오인 |
| L2 | `newHash`를 **쓰기 전 `updatedAt`**으로 계산 | `main.py:253`, `:298` | Wiki.js가 쓰기 후 `updatedAt` 갱신 → `newHash`는 실제 hash와 **절대 불일치**. 연속 patch 시 항상 충돌 |
| L3 | `upsert`는 hash 검사 없음 | `main.py:384` | 동시 편집 유실 (lost update) |
| L4 | 검사(read)→쓰기(update) 비원자적 | `main.py:288`→`:303` | Wiki.js GraphQL에 조건부 update 없음. 틈 사이 편집 덮어씀, 읽어둔 title/tags 되돌림 |

### v2 계약

1. hash 정의 불변: `"sha256:" + hex(sha256(id + "\n" + updatedAt + "\n" + content))`.
   **`updatedAt`은 Wiki.js가 준 문자열 그대로** (Rust판: 날짜 타입으로 파싱·재직렬화 금지).
2. 조회 응답의 `contentHash`를 쓰기 body의 `baseHash`로 보낸다 (헤더 불필요 → MCP tool 동일).
3. 불일치 → **409** `page-changed` + `currentHash`. `patches/preview`도 동일.
   (412는 `If-Match` 헤더용. body 기반 계약이므로 409. GET `ETag`는 편의 제공, `If-Match`는 v2 범위 밖)
4. **쓰기 성공 후 재조회**: Wiki.js update 성공 → 같은 path·locale을 다시 조회 → 실제 `contentHash`를 응답 `contentHash` 필드로 반환 (`newHash` 필드 제거).
   - 재조회 실패 시: 쓰기는 이미 성공했으므로 **200 유지**, `contentHash: null` + 응답 헤더 `Warning`/필드 `refetchFailed: true`. 클라이언트는 다음 쓰기 전 재조회.
   - audit의 `new_hash`도 재조회 값으로 기록.
5. upsert: 기존 페이지 **수정** 시 `baseHash` 필수 (누락 428, 불일치 409). 생성 시 불필요. 응답에 재조회 `contentHash`.
6. L4 완화: gateway 프로세스 내 **페이지 단위 직렬화** (key = `locale:path`).
   - 검사 → 쓰기 → 재조회를 같은 lock 안에서 수행.
   - 단일 인스턴스 전제. 수평 확장 시 무효 → 문서화.
   - Wiki.js UI 직접 편집과의 경합은 잔여 위험으로 문서화.

### 쓰기 시퀀스

```
client                 gateway                         Wiki.js
  │ PUT/POST + baseHash   │                               │
  │──────────────────────▶│ lock(locale:path)             │
  │                       │── get page ──────────────────▶│
  │                       │◀───────── page ───────────────│
  │                       │ hash != baseHash → 409 (unlock)
  │                       │── update ────────────────────▶│
  │                       │◀───────── ok ─────────────────│
  │                       │── get page (refetch) ────────▶│
  │                       │◀───────── page ───────────────│
  │                       │ audit(new_hash=refetched)     │
  │                       │ unlock                        │
  │◀── 200 {contentHash} ─│                               │
```

## 6. 충돌 방지 가드

| # | 충돌 | 가드 |
|---|---|---|
| G1 | Wiki.js 페이지 `api/...`가 gateway 경로에 가려짐 | gateway 쓰기(upsert/patches)가 첫 세그먼트 `api` 경로를 422 `reserved-path`로 거부 + 운영 안내(§8). 관리자 그룹은 page rule 우회 → 잔여 위험 문서화 |
| G2 | proxy 설정 누락 시 Wiki.js catch-all이 **200 HTML** 반환 | `X-Served-By` 헤더. 계약 테스트·운영 점검에서 확인 |
| G3 | FastAPI 기본 `/docs` `/redoc` `/openapi.json` | `/api/v2/openapi.json`만 노출, 나머지 비활성 |
| G4 | rmcp `allowed_hosts` 기본값(loopback) → 공개 호스트명의 `/mcp` 거부 | Rust판 환경 변수 `MCP_ALLOWED_HOSTS` |
| G5 | Wiki.js 세션 쿠키 | gateway는 Bearer만 신뢰, 쿠키 미사용 |

## 7. 정책 대비 수정 사항 (Deviation)

| 정책 | 이 프로젝트 | 사유 |
|---|---|---|
| `/api/v{major}/{service}/...` | `/api/v2/...` (service slug 없음) | 공유 호스트 전체가 wiki. gateway가 `/api/` 유일 소유자 |
| 동사 경로 금지 | `search`, `batch-get`, `patches/preview`, `raw` 허용 | 도메인 액션. OpenAPI에 예외 명시 |
| `/api/` 유일 소유 보장 | Wiki.js가 이론상 `api/` 페이지 생성 가능 | Wiki.js에 경로 예약 설정 없음 → G1 |
| problem+json | REST만. MCP 오류는 `isError` 결과 | MCP는 HTTP 오류 계약 밖 |
| traceparent | 수신 시 audit 기록·Wiki.js 호출에 전달 | 생성은 proxy 책임 |

## 8. 운영자 안내 — Reverse proxy (사용자 설정, 소스 구현 아님)

README에 게재한다. 요구 사항 (proxy 종류 무관):

1. `/api/v2/` prefix → gateway, 나머지 → Wiki.js. **prefix 매칭이 catch-all보다 우선**.
2. 경로 재작성 금지 (prefix strip 하지 않음).
3. gateway 경로에서 `Cookie` 헤더 제거.
4. gateway 경로 응답 버퍼링 끔, read timeout 300s 이상 (MCP SSE).
5. Wiki.js 경로는 WebSocket upgrade 허용 (GraphQL subscriptions).
6. `X-Forwarded-For` / `X-Forwarded-Proto` 설정. gateway는 proxy IP만 신뢰 (`FORWARDED_ALLOW_IPS`).
7. Wiki.js 관리자 → Groups → Page Rules: `api` 경로 시작(START) write 거부.

nginx 예시:

```nginx
location /api/v2/ {
    proxy_pass http://wikijs-gateway:8080;   # no URI part -> path preserved
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header Cookie "";
    proxy_buffering off;
    proxy_read_timeout 300s;
    client_max_body_size 5m;
}
location / {
    proxy_pass http://wiki:3000;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
}
```

점검: `https://<wiki-host>/api/v2/openapi.json` 응답에 `X-Served-By: wikijs-gateway`가 있어야 한다.

## 9. 구현 범위 (FastAPI / Rust)

| 항목 | FastAPI판 | Rust판 (Axum + rmcp) |
|---|---|---|
| 라우트 | `APIRouter(prefix="/api/v2")`, operation_id 유지 | `Router::nest("/api/v2", ..)` |
| MCP | fastapi-mcp mount 경로 `/api/v2/mcp` | rmcp `StreamableHttpService` nest, stateless, `allowed_hosts` |
| OpenAPI | `openapi_url="/api/v2/openapi.json"`, `docs_url=None`, `redoc_url=None` | `utoipa`로 동일 문서 생성 |
| problem+json | exception handler 일원화 (`RequestValidationError` 포함) | 공통 오류 타입 + `IntoResponse`, 추출기 거부도 변환 |
| 잠금 | 409/428, 재조회, `asyncio.Lock` per key | 동일, `tokio::sync::Mutex` per key |
| hash | 기존 `locking.py` | `updatedAt` 문자열 그대로, 결과 바이트 동일 |
| G1 | 쓰기 경로 검사 | 동일 |
| `X-Served-By` | middleware | tower layer |
| health | `/health/live`, `/health/ready` | 동일 |
| 토큰 비교 | `hmac.compare_digest` | `subtle::ConstantTimeEq` |

## 11. 검증 (계약 테스트, 두 판 공통)

1. 직접 호출: `:8080/api/v2/...` → 두 판 동일 응답, 동일 `openapi.json`
2. 모든 응답 `X-Served-By`
3. 잠금: 불일치 409 / 수정 upsert `baseHash` 누락 428 / 쓰기 응답 `contentHash`로 즉시 연속 patch 성공 / 동일 페이지 동시 patch 2건 중 1건만 성공(나머지 409)
4. G1: `api/...` 쓰기 422
5. MCP: `tools/list` 스냅샷, 쓰기 tool 토큰 없이 거부, 409가 `isError`로 전달
6. 이전 경로(`/pages/*`, `/health`, `/mcp`) 404
7. 오류 응답 `Content-Type: application/problem+json`

proxy 경유 검증은 운영자 점검 항목(§8).
