개요 & 인증

Wiki.js GraphQL API 앞에 위치하는 안전 제한 게이트웨이.
모든 요청은 아래 헤더가 필요하다.

Authorization: Bearer <GATEWAY_TOKEN>
헤더 누락 또는 토큰 불일치 시 401 Unauthorized 반환.
항목값
Base URLhttp://127.0.0.1:8088
Content-Type (요청 body)application/json
인증Bearer token (GATEWAY_TOKEN 환경 변수)
기본 localeDEFAULT_LOCALE 환경 변수 (기본: ko)

Gateway 모드

모드ENV 값허용차단기본
read_onlyGATEWAY_MODE=read_only health, page 조회dry-run, 쓰기
dry_runGATEWAY_MODE=dry_run read + patch 계산 + diff 반환실제 Wiki.js mutation✅
writeGATEWAY_MODE=write ALLOW_PATH_PREFIXES 내 create/updateallowlist 외 경로 쓰기

엔드포인트

GET /health read_only 이상

서비스 상태 및 Wiki.js 연결 가능 여부를 반환한다.

응답 (200 OK)

필드타입설명
okboolean항상 true
modestring현재 Gateway 모드 (read_only | dry_run | write)
wikijsReachablebooleanWiki.js GraphQL endpoint 응답 여부

예시

# Request
curl -H "Authorization: Bearer $GATEWAY_TOKEN" \
     http://127.0.0.1:8088/health

# Response
{
  "ok": true,
  "mode": "dry_run",
  "wikijsReachable": true
}
GET /pages/by-path read_only 이상

Wiki.js 페이지를 path + locale로 조회한다. 응답에 contentHash가 포함되어 optimistic locking에 사용된다.

Query Parameters

파라미터필수타입설명
path필수stringWiki.js 페이지 경로 (예: /agent/test)
locale선택stringlocale 코드. 생략 시 DEFAULT_LOCALE 사용

응답 (200 OK) — PageResponse

필드타입설명
idintegerWiki.js 내부 페이지 ID
pathstring페이지 경로 (leading slash 없음)
localestring페이지 locale
titlestring페이지 제목
descriptionstring페이지 설명
contentstringMarkdown 본문
editorstring편집기 타입 (예: markdown)
isPublishedboolean공개 여부
isPrivateboolean비공개 여부
updatedAtstringISO8601 최종 수정 시각
contentHashstringsha256(id + updatedAt + content) — locking용 baseHash
tagsstring[]태그 목록
scriptCssstring | null커스텀 CSS
scriptJsstring | null커스텀 JS

예시

curl -H "Authorization: Bearer $GATEWAY_TOKEN" \
     "http://127.0.0.1:8088/pages/by-path?path=/agent/test&locale=ko"

POST /pages/dry-run dry_run 이상

실제 Wiki.js에 쓰지 않고 patch 결과와 diff만 반환한다. optimistic lock 검증을 수행한다.

예시

curl -X POST http://127.0.0.1:8088/pages/dry-run \
  -H "Authorization: Bearer $GATEWAY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "path": "/agent/test",
    "baseHash": "a3f8c2...",
    "operation": {
      "type": "replace_between_markers",
      "name": "status",
      "content": "배포 완료"
    }

에러

상태error 코드설명

Patch Operation 타입

dry-run과 patch-section 요청의 operation 필드에 사용한다.

replace_between_markers 권장 — 반복 업데이트에 안전

<!-- agent:start {name} --> … <!-- agent:end {name} --> 사이 내용을 교체한다.
마커가 없으면 422 PATCH_ERROR.

필드필수설명
type필수"replace_between_markers"
name필수마커 이름 (예: "status")
content필수교체할 새 내용
# Markdown 내 마커 형식
<!-- agent:start status -->
기존 내용이 여기에 있음
<!-- agent:end status -->
append_under_heading

지정한 heading 아래에 내용을 추가한다. heading 정확 일치 필요.

필드필수설명
type필수"append_under_heading"
heading필수heading 텍스트 (예: "## 변경 이력")
content필수추가할 내용
create_heading선택false (기본) — heading 없으면 에러 / true면 자동 생성
replace_section

heading 전체 section(다음 같은-수준 heading 직전까지)을 교체한다. 통제된 문서에서만 사용 권장.

필드필수설명
type필수"replace_section"
heading필수대상 heading 텍스트
content필수새 section 내용 (heading 포함)

Optimistic Locking

동시 수정 충돌을 방지하기 위해 hash 기반 낙관적 잠금을 사용한다.

단계설명
1. 조회GET /pages/by-path로 페이지를 가져오면 contentHash가 포함된다
2. 저장응답의 contentHash를 baseHash로 사용하여 patch 요청
3. 검증Gateway가 현재 페이지 hash와 baseHash를 비교
4. 충돌불일치 시 PAGE_CHANGED + currentHash 반환 → 재조회 후 재시도
# hash 계산식
baseHash = sha256(f"{page.id}\n{page.updatedAt}\n{page.content}")
