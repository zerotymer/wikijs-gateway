  • ✓ allowlist 미포함 경로 → HTTP 403 (PATH_NOT_ALLOWED)

  • ✓ POST /pages/upsert — 신규 page 생성(created: true) 및 기존 page 덮어쓰기(created: false)
  • ✓ GATEWAY_MODE=read_only → POST /pages/patch-section 403 차단
  • ✓ GATEWAY_MODE=dry_run / read_only → POST /pages/upsert 403 차단
  • ✓ baseHash 불일치 → PAGE_CHANGED 응답
  • ✓ audit 파일: {YYYY}/{MM}/{DD}/{ts}_{slug}.json + .diff 분리 저장
  • ✓ audit 쓰기 실패 → 서비스 중단 없이 로그만 출력
  • ✓ WikiJsClient.update_page — 기존 metadata 보존, overrides 적용
  • ✓ WikiJsClient.create_page / upsert_page 구현
  • ✓ 지시서 완료 처리 → instructions/.completed/

5. 아키텍처 개요

Step 4에서 GATEWAY_MODE=write일 때만 Wiki.js mutation을 호출한다. dry_run 모드에서는 patch 계산·diff 반환만 수행하고, 모든 경우에 audit 파일이 생성된다.

6. 구현 단계

app/audit.py — 신규 파일
AuditRecord dataclass 정의. write_audit(record, audit_dir): {YYYY}/{MM}/{DD}/{ts}_{slug}.json + .diff 분리 저장. audit 실패 시 logger.exception만 출력하고 요청을 계속 처리.
app/wikijs_client.py — update_page / create_page / upsert_page 추가
_MUTATION_UPDATE_PAGE, _MUTATION_CREATE_PAGE GraphQL 쿼리 추가. update_page는 기존 page metadata를 기본값으로 보존하고 overrides만 덮어씀. upsert_page는 get_page_by_path 결과에 따라 update/create 분기.
app/models.py — PatchSectionRequest/Response, UpsertRequest/Response 추가
기존 stub(# Step 4 주석) 제거 후 실제 pydantic 모델 4개 추가. PatchSectionResponse에 pageId 포함.
app/main.py — POST /pages/patch-section 엔드포인트
모드 게이트(≥ dry_run) → page 조회 + hash 검증 → patch 계산 → audit 준비. write 모드일 때만 check_path_allowed + update_page 호출. 모든 경우 audit 기록.
app/main.py — POST /pages/upsert 엔드포인트
모드 게이트(≥ write) → check_path_allowed → upsert_page 호출 → audit 기록. created 플래그로 신규/덮어쓰기 구분.
app/main.py — check_path_allowed 공통 함수 추출
ALLOW_PATH_PREFIXES와 path prefix 매칭. 미포함 시 403 PATH_NOT_ALLOWED 반환.
tests/test_audit.py — 6 cases
JSON/diff 파일 생성, 경로 슬러그 변환, diff 없을 때 .diff 미생성, 부모 디렉터리 자동 생성, 잘못된 경로에서 예외 미발생.
tests/test_routes_write.py — 12 cases
dry_run diff-only + audit 생성, write mutation 호출, PATH_NOT_ALLOWED 403, MODE_NOT_ALLOWED 403, PAGE_CHANGED 응답, upsert create/update/block 케이스.
