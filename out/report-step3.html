5. 아키텍처 개요

Step 3 엔드포인트(POST /pages/dry-run)는 Wiki.js에서 페이지를 읽기만 한다. 실제 mutation은 Step 4에서 구현한다.

6. 구현 단계

app/locking.py — compute_hash 형식 수정 + verify_hash 추가
반환값을 raw hex에서 "sha256:{hex}" 형식으로 변경. verify_hash(expected, page_id, updated_at, content) → bool 구현.
app/markdown_patch.py — 신규 파일
HeadingNotFoundError, MarkerNotFoundError 예외 클래스 정의. append_under_heading, replace_between_markers, replace_section, compute_diff 구현.
app/models.py — 4개 모델 추가
PatchOperation (Literal type union), DryRunRequest, DryRunResponse, PageChangedResponse.
app/main.py — require_mode + POST /pages/dry-run
_MODE_ORDER 리스트 기반 require_mode 헬퍼 추출. dry-run 엔드포인트: auth → mode gate → page fetch → hash verify → patch → diff → response.
tests/test_locking.py — 6개 유닛 테스트
format, determinism, different-inputs, verify match/mismatch, stale-updated_at.
tests/test_markdown_patch.py — 16개 유닛 테스트
append_under_heading × 5, replace_between_markers × 4, replace_section × 4, compute_diff × 3.
tests/test_wikijs_client.py — test_compute_hash_format 수정
기존 테스트가 raw hex를 기대하고 있어 새 "sha256:{hex}" 형식에 맞게 수정.
